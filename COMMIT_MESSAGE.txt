fix: resolve Jenkins pipeline serialization error and improve E2E test handling

## Problem
- Jenkins pipeline build #45 failed with java.io.NotSerializableException: java.util.regex.Matcher
- E2E test container ran but produced no visible output
- No fallback mechanism when test summary file wasn't generated

## Root Cause
1. **Serialization Error**: Jenkins CPS (Continuation Passing Style) cannot serialize
   Matcher objects created by String.split() method inside closures
2. **Missing Error Handling**: Pipeline didn't handle missing e2e-test-summary.json file
3. **Poor Output Visibility**: E2E runner had no logging/debugging output

## Solution

### 1. Jenkinsfile - Fixed Serialization (Line 307-350)
- Replaced `eachLine` closure with safe string parsing using `indexOf()` and `substring()`
- Added comprehensive error handling and try-catch blocks
- Implemented fallback mechanism to create default summary when file is missing
- Added debug logging to track exit code parsing

**Before**:
```groovy
e2eOutput.eachLine { line ->
    if (line.startsWith('E2E_EXIT_CODE:')) {
        actualExitCode = line.split(':')[1].toInteger() // ❌ Creates non-serializable Matcher
    }
}
```

**After**:
```groovy
def lines = e2eOutput.split('\n')
for (int i = 0; i < lines.length; i++) {
    def line = lines[i]
    if (line.indexOf('E2E_EXIT_CODE:') >= 0) {
        def colonIndex = line.indexOf(':')
        if (colonIndex >= 0 && colonIndex < line.length() - 1) {
            def exitCodeStr = line.substring(colonIndex + 1).trim()
            actualExitCode = exitCodeStr.toInteger() // ✅ Safe parsing
        }
        break
    }
}
```

### 2. Dockerfile.e2e - Enhanced Output & Error Handling
- Created custom entrypoint script `/app/run-tests.sh`
- Added environment variable logging for debugging
- Improved test execution status reporting
- Ensured Playwright output is always visible

**Benefits**:
